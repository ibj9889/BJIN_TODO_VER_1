# 반복 문서(docx) 편집 가이드 — 표 손상 방지

일일업무보고·주간회의 발제문서처럼 **매번 같은 템플릿을 재사용하는 docx**를 다룰 때 지키는 규칙. todo-log·todo-briefing 스킬에서 표를 수정할 때 이 문서를 먼저 읽는다.

## 절대 규칙: 새로 만들지 말고 "복사 후 편집"

전날(또는 가장 최근) 최종본 docx를 복사해서 시작한다. `docx`(npm) 같은 라이브러리로 문서를 처음부터 새로 생성하지 않는다 — 내용은 맞아도 원본의 세부 서식(정렬, 행 높이, 세로정렬 등)이 미묘하게 달라진다.

방법: `unzip`으로 `word/document.xml`을 풀고 텍스트 치환(정규식)으로만 편집한 뒤 다시 `zip`으로 묶는다.

## 함정 1 — self-closing 빈 셀 태그

행(`<w:tr>`)을 복제해서 새 행을 만들 때, 템플릿으로 삼은 셀이 **내용 없는 빈 셀**이면 `<w:p/>`처럼 self-closing 태그로 저장돼 있을 수 있다. 이걸 열린 태그로 착각하고 뒤에 내용을 이어 붙이면 `</w:p>`가 짝 없이 남아 파일이 손상된다. 반드시 self-closing 케이스를 감지해서 `<w:p ...>`(여는 태그)로 정규화한 뒤 채운다.

## 함정 2 — 표 전체를 갈아치우면 tblPr/tblGrid가 날아간다 (가장 흔한 사고)

표의 행을 일부 유지하고 일부만 바꿀 때, `<w:tbl>...</w:tbl>` 범위 전체를 새 내용으로 덮어쓰면 **표 여는 태그(`<w:tbl>`)·`<w:tblPr>`·열 너비 정의(`<w:tblGrid>`)와 닫는 태그(`</w:tbl>`)가 통째로 날아간다.** 겉보기엔 XML 정합성 검사(`xml.dom.minidom.parseString` 등)를 통과할 수도 있지만, 실제로는 표 하나가 옆 표와 합쳐지거나 사라진다.

**올바른 패턴**: 표 전체가 아니라, 원본 조각에서 "첫 행 시작 전"과 "마지막 행 끝난 후"만 남기고 그 사이만 교체한다.

```python
t = xml[table_start:table_end]
rows = get_rows(t)
new_t = t[:rows[0].start()] + 새_행들_xml + t[rows[-1].end():]
```

표를 여러 개 다룰 때는 이 로직을 **함수 하나로 통일**해서 모든 표에 동일하게 적용한다 — 표마다 손으로 따로 코딩하면 한 곳만 빠뜨리기 쉽다.

## 검증은 반드시 두 가지를 같이 한다

1. `xml.dom.minidom.parseString()` — XML 정합성(태그 짝)만 확인. 함정 2는 이것만으로 못 잡는다.
2. **원본과 표 개수·표별 행 개수를 비교하는 카운트 검증** — 함정 2로 인한 표 병합/손상은 이것으로만 잡힌다.

```python
tables_after = get_tables(xml)
assert len(tables_after) == ORIG_TABLE_COUNT
for i, (s, e) in enumerate(tables_after):
    print(f"table {i}: {len(get_rows(xml[s:e]))} rows")
```

## 한 셀 안에 여러 줄(문단)이 있는 경우

기타사항처럼 "라벨: 값" 여러 줄을 한 셀에 담는 표는, 실제로는 **하나의 `<w:tc>` 안에 여러 개의 `<w:p>`**로 이루어져 있다(줄바꿈마다 별도 문단). 첫 번째 `<w:p>`만 붙잡는 헬퍼를 그대로 쓰면 여러 줄이 한 줄로 뭉개진다. 이런 표는 raw XML에서 `<w:p>` 개수를 먼저 확인하고, 줄 수만큼 문단을 만드는 전용 빌더를 쓴다.

## Windows 콘솔 인코딩 주의

한글 텍스트를 `print()`로 콘솔에 출력하면 콘솔 코드페이지(cp949 등) 때문에 깨져서 표시될 수 있다. 검증 결과는 콘솔에 출력하지 말고 UTF-8 파일로 저장한 뒤 파일을 읽어서 확인한다. `\uXXXX` 이스케이프를 손으로 계산해서 쓰지 말고, 항상 리터럴 UTF-8 한글을 직접 쓴다 — 손 계산은 오탈자가 나기 쉽다.
