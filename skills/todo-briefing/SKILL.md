# 모드 C: 주간회의 발제 문서

`TASKS.md`/`tasks/*.md`/`logs/WORK-LOG-*.md`의 이번 주 활동을 회사 공식 양식 docx로 정리한다.

## 절대 규칙: 새로 만들지 말고 "복사 후 편집"

가장 최근에 제출한 발제문서 docx가 있으면 그걸 복사해서 시작한다. `references/docx-editing-guide.md`를 따라 `word/document.xml`만 편집한다. 이 플러그인은 회사마다 다른 발제문서 양식을 알지 못하므로, **첫 실행 시 가장 최근 발제문서 docx 파일 경로를 사용자에게 물어본다.**

## 내용 채우기 규칙

1. **확인되지 않은 내용은 지어내지 않는다.** 이번 주 실제로 진행된 것이 확인 안 되면 빈칸으로 두지 말고 `[내용 입력 필요]`라고 표시해서, 사용자가 직접 채우거나 알려주도록 한다.
2. 프로젝트 표기는 사용자 회사의 실제 관례를 따른다(예: "업체명-고객사명" 형식처럼) — `REFERENCE.md`의 프로젝트 표를 참고하고, 처음 접하는 표기 관례가 있으면 사용자에게 확인 후 `REFERENCE.md`에 기록해 다음부터 재사용한다.
3. 표에 새로운 섹션(예: 별도 취합 보고)을 추가해야 하면, 기존 표의 스타일(테두리·음영·폰트)을 그대로 복제해서 이질감이 없게 만든다.
4. 문체는 `references/natural-writing-style.md`를 따른다 — 표의 모든 행이 같은 문장 공식을 반복하지 않도록 한다.

## 편집 시 검증

표를 수정한 뒤에는 반드시:
1. `xml.dom.minidom.parseString()`으로 XML 정합성 확인
2. 원본과 표 개수·표별 행 개수를 비교하는 카운트 검증

두 가지를 빠짐없이 한다 — `references/docx-editing-guide.md`의 "함정 2"가 정합성 검사만으로는 안 잡힌다.

## 완료 후

만든 파일을 어디 저장했는지 명확히 알려주고, `logs/WORK-LOG-*.md`에 산출물 경로를 기록한다.
