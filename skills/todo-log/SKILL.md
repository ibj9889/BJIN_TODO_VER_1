# 모드 A: 개인 업무 기록 (기본값)

날짜와 항목만 보내면 개인 TODO로 처리한다. 팀원 여러 명의 주간보고를 한꺼번에 붙여넣은 경우는 `todo-weekly-report` 스킬로, 주간회의 발제 문서 요청은 `todo-briefing` 스킬로 넘긴다.

먼저 이 폴더에 `CLAUDE.md`·`TASKS.md`가 있는지 확인한다. 없으면 `todo-setup` 스킬로 초기 설정부터 안내한다.

## 입력 예시
```
9/15
- 고객 미팅 2시간
- A대리 회신 확인
- 버그 3건 수정 완료
```

## 기록 형식 (logs/WORK-LOG-YYYY-MM.md에 추가)
```
**[태그] 한 줄 제목**
- 내용:
- 상태: 완료 / 진행중 / 보류 / 예정
- 담당: (본인 외일 때만)
- 프로젝트:
- 후속조치:
- 키워드: 프로젝트명, 시스템명, 관련자
```

## 태그
`#개발` `#회의` `#문서` `#고객대응` `#이슈` `#교육` `#팀관리` `#기타`

## 규칙

1. 날짜를 안 적으면 오늘로 기록한다. "어제", "지난주 화요일"은 실제 날짜로 변환해 확정한다 — 시스템 날짜를 먼저 확인한다.
2. 여러 건을 한 번에 적으면 항목별로 분리해 각각 기록한다.
3. 키워드 줄은 반드시 넣는다.
4. **애매하면 추측하지 말고 한 번만 되묻는다.** 같은 질문을 반복하지 않는다. 정말 애매해서 확답을 못 받으면 `REFERENCE.md`의 미확인 항목 표에 남기고 넘어간다.
5. 미완 항목은 다음 날로 이월하고 `(N/N 이월)`을 표기한다. 이월 횟수가 3회를 넘으면 사용자에게 알려준다.
6. 프로젝트명이나 분류가 바뀌면 즉시 반영하고, 로그에 변경 이력을 남긴다 (`REFERENCE.md` 프로젝트 표도 갱신).
7. **로그 파일 + 해당 주제 `tasks/*.md` + `TASKS.md` 인덱스 한 줄, 이 3곳을 같이 갱신한다.** 어느 주제 파일에 속하는지 먼저 판단 — 기존 주제와 가까우면 그 파일에, 완전히 새로운 주제면 새 `tasks/*.md` 파일을 만들고 `TASKS.md`에 한 줄 추가한다. 완료 항목은 해당 파일의 Done 섹션으로 옮긴다.
8. 이름·프로젝트 확인이 필요하면 `REFERENCE.md`를 읽는다.
9. **팀원에게 위임한 업무는 팀원 이름으로 귀속한다.** 사용자가 "오늘 이거 했어"라고 말해도, 그 업무가 이전에 다른 사람에게 인계된 이력이 있으면 그 사람 이름으로 기록한다 — 애매하면 확인 질문을 하거나 두 가능성을 열어둔다.
10. 문서(docx 등)를 작성할 때는 `references/natural-writing-style.md`를 따르고, 기존 파일을 편집할 때는 `references/docx-editing-guide.md`의 함정들을 먼저 확인한다.

## 반복되는 일일 보고서(docx)를 함께 쓰는 경우

회사 양식으로 매일 일일업무보고 docx를 제출해야 한다면:

1. **절대 새로 생성하지 않는다.** 전날(또는 가장 최근) 최종본을 복사해서 시작하고, `word/document.xml`만 텍스트 치환으로 편집한다. `references/docx-editing-guide.md`를 반드시 따른다.
2. 표가 여러 개(주간 주요업무 / 금일 업무 / 팀원 업무 / 기타사항 등)라면, 각 표를 같은 헬퍼 함수로 통일해서 편집하고 편집 후 표 개수·행 개수를 원본과 비교 검증한다.
3. 팀원별 업무 표에 **항상 이름을 올려야 하는 고정 팀원**이 있다면(사용자가 지정), 그날 특별히 보고된 내용이 없어도 이름 행은 유지하고 "확인 필요"로 표시한다 — 표 자체에서 빠뜨리지 않는다.
4. 한 셀 안에 여러 줄(라벨: 값 형태)이 들어가는 표는 실제로 여러 개의 문단으로 구성돼 있을 수 있다 — 한 줄로 뭉개지 않는다.
5. 처음 며칠은 사용자가 초안을 직접 고쳐서 다시 준다 — 그 수정 내용에서 패턴을 뽑아 `daily-report-patterns.md`(사용자 폴더에 직접 생성) 같은 파일에 누적하고, 다음 초안부터 선반영한다. 같은 실수를 반복하지 않는 것이 핵심이다.
