# 초기 설정

`BJIN_TODO_VER_1` 플러그인을 처음 쓰는 사용자를 위한 온보딩 스킬. 이 스킬이 끝나면 `todo-log`/`todo-weekly-report`/`todo-briefing`이 바로 동작할 수 있는 개인화된 파일 구조가 만들어진다.

## 언제 실행하는가

- 사용자가 명시적으로 초기 설정을 요청했을 때
- 또는 `todo-log` 등 다른 스킬이 호출됐는데 현재 폴더에 `CLAUDE.md`나 `TASKS.md`가 없을 때 (다른 스킬이 이 스킬로 안내한다)

이미 `CLAUDE.md`가 있으면 "이미 설정된 것 같은데 다시 설정할지" 확인하고, 재설정이 아니면 진행하지 않는다.

## 절차

### 1. 질문하기

한 번에 다 묻지 말고 대화하듯 자연스럽게 물어본다. 최소한 아래 정보가 필요하다 — 순서·표현은 자유롭게 바꿔도 된다.

1. **이름 / 직급 / 소속팀(부서)** — 예: "홍길동 / 과장 / 개발2팀"
2. **팀원 구성** — 같이 일하는 팀원 이름·직급 (없으면 생략 가능)
3. **담당 프로젝트 목록** — 진행 중인 프로젝트/고객사 이름을 간단히
4. **주간보고를 제출하는지, 제출한다면**:
   - 누구에게 보내는지, 언제(요일·시간) 마감인지
   - **실제로 예전에 보냈던 주간보고 이메일 1~3통을 그대로 붙여넣어 달라고 요청한다.** 이게 형식을 정확히 잡는 가장 중요한 입력이다 — 없으면 "일반적인 형식"으로 시작하되, 나중에 실제 사례가 생기면 그때 형식을 맞추자고 안내한다.
5. **정기 일정** — 매주 반복되는 회의/보고 일정 (요일, 시간, 이름)
6. **파일을 저장할 폴더 경로** — 기본값은 현재 폴더

### 2. 파일 생성

`templates/` 아래 템플릿을 읽고, 위 답변으로 `{{PLACEHOLDER}}`를 채워서 아래 파일들을 사용자가 지정한 폴더에 생성한다.

| 생성 파일 | 원본 템플릿 |
|---|---|
| `CLAUDE.md` | `templates/CLAUDE.md.template` |
| `REFERENCE.md` | `templates/REFERENCE.md.template` |
| `TASKS.md` | `templates/TASKS.md.template` |
| `logs/WORK-LOG-{이번달}.md` | `templates/WORK-LOG.template.md` |

추가로:
- `tasks/` 빈 폴더를 만든다 (실제 업무가 생기면 `todo-log`가 주제별 파일을 그 안에 만든다).
- 실제 주간보고 예시를 받았다면 `reference/주간보고_실제양식_참고.md`에 원문 그대로(요약하지 않고) 저장하고, "핵심 규칙" 요약을 맨 위에 붙인다. `todo-weekly-report`는 이 파일을 형식의 근거로 삼는다.
- 이 플러그인의 `references/natural-writing-style.md`·`references/docx-editing-guide.md`도 사용자 폴더의 `references/`로 복사한다 (다른 스킬들이 상대경로로 참조하기 때문).

### 3. git 초기화 (선택)

버전 관리를 원하는지 물어본다. 원하면:
```
git init
git add -A
git commit -m "BJIN_TODO 초기 설정"
```
원격 저장소(GitHub 등)에 올릴지는 별도로 물어본다 — 원격 추가·푸시는 사용자 확인 없이 하지 않는다.

### 4. 완료 안내

무엇을 만들었는지 요약하고, 앞으로는 그냥 날짜+할 일을 말하면 `todo-log`가 자동으로 기록한다는 걸 알려준다. 예: "9/15 - 고객 미팅 2시간, 버그 3건 수정" 처럼 편하게 말하면 된다고 안내한다.

## 규칙

- 사용자가 답하기 애매해하는 항목(팀원 구성 등)은 생략 가능하게 하고, 나중에 채워도 된다고 안내한다 — 처음부터 다 채우라고 강요하지 않는다.
- 입력받은 내용을 그대로 반영한다 — 임의로 각색하거나 예시를 지어내서 채우지 않는다.
- 문서 작성 톤은 `references/natural-writing-style.md`를 따른다.
