# 모드 B: 팀 주간보고 취합

여러 팀원의 주간 업무 내용을 모아 상급자에게 보내는 실제 이메일 형식으로 정리한다.

## 형식의 근거 — 반드시 실제 사례를 따른다

**절대 일반적인/상상한 기업 템플릿을 쓰지 않는다.** `reference/주간보고_실제양식_참고.md`(설정 시 저장됨)에 사용자가 실제로 예전에 보냈던 이메일 원문이 있으면 그 형식을 그대로 따른다.

이 파일이 아직 없거나 비어 있으면, 작업을 시작하기 전에 **실제로 보냈던 주간보고 이메일 1~3통을 붙여넣어 달라고 요청한다.** 형식을 추측해서 화려한 섹션 구조(핵심성과/이슈및지원요청/부록 같은)를 만들지 않는다 — 실제 사례가 쓰는 형식이 곧 정답이다.

## 작성 규칙

1. 팀원별 원문 내용을 프로젝트별로 재구성한다. 같은 프로젝트를 여러 사람이 언급했으면 합쳐서 정리한다.
2. **위임된 업무는 실제로 처리한 사람 이름으로 귀속한다** — `TASKS.md`/`tasks/*.md`에서 위임 이력을 확인한다.
3. "제출했다"는 사실 자체는 내용이 아니다 — 실제로 한 일만 적는다.
4. 이미 이전 보고에서 다룬 배경 설명(조직 개편 등)은 반복하지 않는다.
5. 문체는 `references/natural-writing-style.md`를 따른다 — 항목마다 같은 접속사·같은 기호를 기계적으로 반복하지 않는다.

## ⚠️ 출력 형식 — 복사-붙여넣기 안전하게

이메일 본문처럼 **사용자가 그대로 복사해서 다른 곳에 붙여넣을 텍스트**는 반드시 코드블록(```) 안에 순수 텍스트로 준다. 코드블록 안에서는:

- 마크다운 굵게(`**text**`)를 쓰지 않는다.
- 실제 원문이 쓰는 기호를 그대로 따른다 — 임의로 다른 기호(・, •, ※ 등)를 섞지 않는다. (기본 관례: 상위 항목은 `*`, 하위 항목은 `-`. 단, 사용자의 실제 사례가 다르면 그걸 우선한다.)

코드블록 바깥의 설명·코멘트는 평소처럼 써도 된다 — 문제는 복사 대상이 되는 본문 안에서만 순수 텍스트를 지키는 것이다.

## 취합 대상

`REFERENCE.md`의 팀 구성표를 참고해 누구를 포함하고 누구를 제외할지 확인한다(제외 대상이 있다면 사용자에게 확인). 사용자 본인 업무도 취합 대상에 포함할지 물어본다.
